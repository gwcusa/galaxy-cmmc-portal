1. PURPOSE
This policy governs the use of temporary passwords for system
logons, requiring users to change temporary passwords upon
first use.

2. WHEN TEMPORARY PASSWORDS ARE USED
Temporary passwords are issued in the following situations:
  - New employee account creation (initial password)
  - User-initiated password reset (forgotten password)
  - Admin-initiated password reset (after lockout or compromise)

3. REQUIREMENTS FOR TEMPORARY PASSWORDS

3.1 Forced Change on First Use
  - All temporary passwords are configured with
    "User must change password at next logon" flag set in AD
  - Users cannot bypass this requirement
  - The temporary password is invalid after first change

3.2 Temporary Password Characteristics
  - Minimum 14 characters (longer than the standard 12)
  - Randomly generated (not predictable patterns like name+date)
  - Communicated to user via phone call or in-person only
    (never sent via the same email the user is logging in with)
  - Valid for 24 hours before automatic expiration if unused

3.3 Communication Method
  - Temporary password communicated by Sandra Okonkwo:
    - For office staff: in person or via phone
    - For remote staff: via encrypted Teams message (if
      Teams account still accessible) or phone call

4. DOCUMENTATION
  Password reset events are logged in Active Directory
  (Event ID 4723/4724) and the IT ticketing system.
