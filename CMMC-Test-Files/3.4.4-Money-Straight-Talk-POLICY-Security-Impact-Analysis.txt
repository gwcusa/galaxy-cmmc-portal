1. PURPOSE
This policy requires that the security impact of proposed
changes to MST information systems is analyzed before
implementation.

2. WHEN ANALYSIS IS REQUIRED
Security impact analysis is required for all Normal and
Emergency changes to:
  - Operating system configurations
  - Security software configurations
  - Network device configurations (firewall, VPN, switches)
  - Applications that process CUI
  - Access control settings (user permissions, group policies)
  - Cryptographic configurations

3. ANALYSIS PROCESS
For each change, Terrell Banks must document:
  a) Description of the change
  b) Systems and data affected
  c) Security controls that may be affected
  d) Potential negative security impacts (if any)
  e) Compensating controls or rollback plan (if negative impacts)
  f) Whether the change introduces new attack surface
  g) Recommendation: APPROVE / DEFER / REJECT

4. APPROVAL
  Camille Odom reviews the security impact analysis before
  approving Normal and Emergency changes.

5. DOCUMENTATION
  Security impact analysis is documented in the Change Request
  ticket in the IT ticketing system.
  Analysis is retained with the change record for 3 years.
